# What a request resolves to

Generated by `resolution_table --write docs/RESOLUTION.md` from the request grid in `tests/grid.hpp`, and checked
against the registry by the `resolution` test: a change to `include/urd/registry/declarations.hpp` that moves a request shows up
here. Each row is a request as written, the properties its spec holds (what the request implies beyond what it
states), the representation chosen, and the headers in `urd/repr/` a file holding such a Store includes: the
container's own, after its part's for a wrapper. This table is built with no container header included:
resolving completes nothing.
A request is one of three things: served; `none` and missing, a
representation that could be written (its note says which); or incompatible, a contract no representation can
keep, which `Store` rejects with a message (the rules are listed in docs/language/index.rst, "Incompatible
combinations"; a request rejected by a rule cannot appear here, one rejected by the registry appears as `none`
with its compile-fail case). `Id` is a key identified by one integral member (hashable, orderable,
indexable).
